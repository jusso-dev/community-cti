# ADR 0007: Magic-link sessions

- Status: Accepted
- Date: 2026-10-14

## Context
People in small organisations need a sign-in path that does not depend on Microsoft 365. Phase 2 can add single sign-on later. The onboarding issue asks for a recorded choice of session mechanism.

## Decision
Use first-party magic-link sessions, in the style of Lucia, with no third-party auth library.

- `POST /auth/magic-link` stores only a hash of the token.
- `GET /auth/callback` creates a session whose token is also stored as a hash.
- Sessions expire after 12 hours.
- Roles are owner, member, credential_viewer and analyst.

## Consequences
There is no external auth dependency to host or upgrade. Password storage is out of scope. Microsoft 365 remains a read-only integration, not the sign-in system, until a later decision.
